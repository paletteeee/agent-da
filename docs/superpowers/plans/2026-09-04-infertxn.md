# InferTxn Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a dependency-free Python prototype that applies MVCC and two-phase commit to atomic KV-cache metadata migration in distributed LLM inference.

**Architecture:** A coordinator drives transactions across three independent participant shards. Each participant wraps an MVCC store; an inference-specific service composes route, KV metadata, and request-state writes into one recoverable transaction.

**Tech Stack:** Python 3.9+ standard library, `unittest`, `http.server`, JSON/JSONL.

**Spec:** `docs/superpowers/specs/2026-09-04-infertxn-design.md`

## Global Constraints

- Keep InferTxn isolated under `src/infertxn/`; preserve existing TxnMem behavior.
- Store KV-cache metadata only, never tensors.
- Claim snapshot isolation, not strict serializability.
- Use no third-party runtime dependency.
- Every production behavior is introduced by a failing test.

**Interfaces:**
- `InferenceMetadataDB.initialize_request(request_id, node, cache_version, generated_tokens=0)` seeds all shards.
